# «ДЗ»: устройство проекта, текущее состояние и дальнейшая работа

Сводный документ на **1 октября 2026**. Проверенная основа: ветка `codex/rebuild`, версия **1.23.57**, последний коммит приложения **747e3be**. Это описание фактического кода и согласованных направлений, а не обещание готовности всех запланированных функций. Основная часть посвящена устройству системы; история и планы собраны в конце.

## 1. Назначение и границы

«ДЗ» — личный учебный планер владельца и нескольких друзей. Основное устройство — iPhone с установленным веб-приложением; интерфейс также работает на компьютере. Продукт объединяет расписание, домашние задания и заметки на день. Это не полноценная корпоративная CRM.

Рабочее приложение сохраняет данные на устройстве и не требует собственного сервера для обычного использования. Дополнительный локальный агент помогает превратить свободный текст или диктовку в предложения заданий. Он ещё не подключён к опубликованному приложению на телефоне.

Три основные вкладки: **Задачи**, **Расписание**, **Настройки**. Выбранный дизайн — A4 «Лист»; A4 здесь название концепции. Принятый ярлык — **«Стопка A с фоном»**. Новые варианты дизайна без отдельного запроса не нужны.

## 3. Общая схема связей

```text
Обычное приложение на iPhone / компьютере
    GitHub Pages → HTML + React + CSS + manifest + service worker
                         │
                         ├─ src/data/schedule.ts: предметы и расписание
                         ├─ функции дат, недель и привязки к занятиям
                         ├─ интерфейс задач, расписания и настроек
                         └─ localStorage: dz-next:v1
                                  └─ ручной экспорт JSON

Локальный пилот агента на MacBook
    браузер → Vite :4175 → proxy /agent/* → Python :4176
       │                                       ├─ аудио → ffmpeg → Parakeet MLX
       │                                       └─ текст + контекст → Claude Code
       │                                                                  │
       │                                                       Claude через Pro
       └─ проверка ответа → расчёт дат → редактируемые карточки
                                            └─ подтверждение → localStorage
```

Parakeet выполняет распознавание локально. Claude обрабатывает текст у провайдера через авторизованный Claude Code. Это не локальная языковая модель. Аудио не требуется отправлять в Claude: после распознавания передаётся текст. Модель не получает инструменты записи заданий, shell или доступ к файлам проекта.

## 5. Данные: что хранится и где

### 5.1. Локальная записная книжка

Основной ключ — **`dz-next:v1`**. Старые ключи `dz:*` рабочая новая версия не использует для чтения и записи. Схема данных имеет собственную версию `1`; она не равна номеру приложения `1.23.57`.

```ts
type Notebook = {
  version: 1
  tasks: DemoTask[]
  theme: 'light' | 'dark' | 'black' | 'system'
  collapsed: string[]               // даты свёрнутых групп
  animationSpeed?: 'fast' | 'normal' | 'smooth'
}

type DemoTask = {
  id: string
  subjectId: string                 // пустая строка допустима
  title: string
  due: string                       // YYYY-MM-DD, уже выбранный срок
  done: boolean
  entryType?: 'homework' | 'note'
  testBatchId?: string
  lessonId?: string
  kind?: 'lecture' | 'seminar' | 'lab' | 'other'
}
```

Название `DemoTask` историческое: этот тип используется и рабочими записями. Черновик `Draft` не содержит обязательных `id` и `done`; у редактируемой записи ID может присутствовать, также есть вспомогательный `locked`.

Расписание и предметы в Notebook не сохраняются: сейчас они поступают из исходного TypeScript-файла. Текущая вкладка, открытое окно, выбранный день, текст агента и его предложения находятся в памяти React, а не в постоянном хранилище.

### 5.2. Проверка и ошибки сохранения

При чтении проверяются версия, поля, реальные календарные даты, уникальные ID, допустимые темы и виды записей. Ошибка чтения блокирует автоматическую запись поверх повреждённых данных. Есть возможность скачать исходное содержимое ключа для восстановления вручную.

Обычные изменения проходят через `useNotebook`; эффект сохраняет новое состояние. Если localStorage недоступен или переполнен, показывается ошибка, а данные текущего сеанса остаются в памяти. Это не облачная резервная копия.

Пакет агента сохраняется иначе: сначала проверяется и записывается целый следующий Notebook, затем обновляется React-состояние и закрывается окно. Ошибка записи оставляет карточки открытыми. Защита от повторного нажатия действует в текущем окне; семантического поиска дубликатов среди старых задач нет.

### 5.3. Экспорт и пределы хранения

Экспорт скачивает JSON записной книжки с задачами и настройками. **Импорта через интерфейс, облачных копий, общей базы и синхронизации нет.** Очистка данных браузера или другой origin могут лишить доступа к сохранённым записям. Нельзя рекомендовать переустановку как обычный способ лечения ошибки без сохранения копии.

## 7. Как рассчитываются дни, недели и сроки

Опорный понедельник — **2026-08-31**, неделя-числитель. `parityOf` сравнивает понедельник выбранной недели с якорем и нормализует остаток для дат до якоря. `lessonsOn` фильтрует правила по дню недели и чётности, затем сортирует по времени начала.

Учебный номер недели — отдельная величина: `academicWeek` считает недели от якоря, а не ISO-недели календарного года. До начала семестра номер отсутствует. Автоматического подтверждённого сброса на весенний семестр нет: дата начала второго семестра и календарь каникул не внесены.

Даты хранятся строками `YYYY-MM-DD`, преобразуются в локальную дату через отдельные функции. Так смена UTC-смещения не должна переносить дедлайн на соседний день. Часы расписания обновляются на границе минуты и при возвращении фокуса/видимости.

У каждой пары собственное время: общей таблицы звонков, которой можно заменить реальные интервалы, нет. `nextLessonDates` ищет ближайшие даты в пределах 60 дней и умеет учитывать вид занятия. Ручные пресеты редактора ищут дни после сегодняшнего; агент отдельно учитывает ещё не начавшиеся пары сегодня. Эти два алгоритма нельзя описывать как полностью одинаковые.

**Сохранённый `due` фиксирован.** Он не пересчитывается при смене расписания. Связь с занятием — дополнение к дате, а не формула плавающего дедлайна.

## 8. Задания, заметки и привязка к паре

Обычное ДЗ ориентировано на **семинар или лабораторную**. Клик по такой паре открывает создание ДЗ. Клик по лекции или ВУЦ (`other`) создаёт заметку с предметом на выбранный день.

`isDayNote` определяет заметку по `entryType: note`, а для старой записи без типа — по отсутствующему предмету. Заметка может иметь предмет. `taskLesson` не прикрепляет заметки к паре: они отображаются отдельно как «Заметки на день».

Для ДЗ явный `lessonId` имеет приоритет. Если такая пара исчезла или несовместима с предметом/видом, функция не выбирает вместо неё первую похожую. Без явного ID автоматическое сопоставление допускается при единственном подходящем семинаре/лабе. Несколько кандидатов требуют выбора.

В ручном редакторе можно выбрать предмет, тип записи, текст, дату, вид занятия и конкретное время пары. Дата без подходящей пары допустима: запись остаётся «Без привязки к паре». Переключение контекста аккуратно пересматривает связь, но не переносит срок само по себе. Предусмотрена совместимость прежних связей с лекциями.

При выводе дня задачи с подходящей связью располагаются внутри пары, остальные ДЗ — в отдельной группе, заметки — внизу дня. План расширить явную связь заметок с парами ещё не равен реализованной функции.

## 9. Интерфейс и основные сценарии

### 9.1. Расписание

Обычный запуск открывает сегодня. Показаны дата, учебная неделя, пары с временем, видом, аудиторией и преподавателем, связанные задания и перерывы. Для дня без пар есть отдельное состояние. Перерывы вычисляются между занятиями; показываются интервалы больше 40 минут. Текущий интервал подсвечивается только на сегодняшней дате.

Дни переключаются стрелками и горизонтальными жестами. Возврат кнопкой «Сегодня» использует анимированный переход. Часы не должны сбрасывать намеренно выбранный другой день: новый день автоматически подхватывается, если пользователь оставался на предыдущем «сегодня».

Календарь открывается по кнопке/номеру недели. Он показывает месячную сетку, номера учебных недель и выбранный день. «Текущий месяц» возвращает только просмотр календаря, не переводит расписание на сегодня и не закрывает окно. Выбор конкретной даты меняет день расписания и закрывает календарь. Кнопка возврата месяца скрыта, когда уже открыт актуальный месяц.

Ряд «Заметка / Задание» закреплён над нижней навигацией отдельно от прокручиваемого содержимого.

### 9.2. Задачи

Активные записи группируются по срокам: «Просрочено», «На завтра», «Актуальная неделя», «Позже». Текущее правило относит к просроченным также невыполненные записи со сроком сегодня. С субботы актуальной считается следующая учебная неделя; воскресные сроки не теряются.

Есть выполнение, редактирование, удаление и кратковременная отмена последнего соответствующего действия. Выполненные записи доступны в истории. История сортируется по сроку, а не по времени выполнения: отдельной метки завершения у текущей схемы нет. Счётчики различают ДЗ и заметки и не включают выполненное.

### 9.3. Настройки

Темы: светлая, тёмная, чёрная, системная. Скорости анимаций: быстрая, обычная, плавная. Есть список предметов и аттестаций, JSON-экспорт, история выполненного, информация о приложении и раздел бета-проверок.

Бета-раздел создаёт и удаляет только помеченные тестовые записи (`testBatchId`). Локальный вход агента расположен здесь и доступен только при `import.meta.env.DEV`. Опубликованная сборка его не показывает.

### 9.4. Окна, жесты, анимации

`Modal` управляет открытием и закрытием; редактор учитывает прокрутку полей и доступность нижних действий. Общие кнопки используют состояние нажатия. Карточка пары затемняет подложку; обводка не является выбранным откликом.

Горизонтальный жест отличают от вертикальной прокрутки; после распознанного свайпа не должен срабатывать клик по паре. Доведение страницы после свайпа сокращено до 70–126 мс, сглаживание следования за пальцем — с постоянной 17 мс. Календарные страницы анимируются отдельно и обрезают собственное содержимое.

CSS-длительности преобразуются с учётом `ms` и `s`, потому что production-сборка может сокращать единицы. `prefers-reduced-motion` имеет приоритет над настройкой скорости. Не следует «улучшать плавность» простым увеличением всех задержек: владелец отдельно просил убрать вязкость свайпов.

## 10. Темы и системная область iOS

Начальный фон и метаданные темы выставляются в `design/index.html` до React, затем синхронизируются из `main.tsx`. Обновляются фон документа и верхней области, а также `theme-color`.

В установленном iOS-приложении наблюдалось сохранение цвета верхней системной полосы после смены темы. Одних обновлений DOM оказалось недостаточно. По прямому разрешению владельца используется обход: сначала сохранить новую тему, затем в standalone при доступной сети выполнить `location.replace` с возвращением в настройки. Для demo, заблокированного хранилища, офлайна и ошибки сохранения reload не выполняется.

Это **обход с перезагрузкой**, а не доказанное исправление внутренних механизмов WebKit. Исторические комментарии в коде о работе «без перезагрузки» не отменяют действующий обработчик `setTheme`.

## 11. Установка, офлайн и обновления

Manifest задаёт русское имя «ДЗ», относительные `start_url`/`scope`, режим standalone и иконки `icon-stack-a-*`. Для iPhone также подготовлена иконка 180 px. Текущий внешний вид ярлыка сохраняется.

`vite.design.config.ts` при сборке подставляет в шаблон worker версию приложения и список файлов оболочки. Имя кеша включает scope и версию. Worker кеширует статические файлы, активируется через `skipWaiting` и получает управление через `clients.claim`.

Для навигации сначала используется сеть; при ошибке или ожидании дольше 3,5 секунды — сохранённая оболочка. Офлайн-работа требует предшествующей успешной загрузки и кеширования. Задания хранятся в localStorage, не в service worker. Старые кеши намеренно не удаляются, чтобы не ломать открытые вкладки.

Регистрация worker проверяет обновления и при возврате приложения на экран. Это не гарантирует мгновенного переключения уже открытой страницы на новый JS. Проверка версии на сайте и проверка установленного ярлыка — разные проверки.

## 12. Локальный агент: компоненты и протокол

### 12.1. Роль каждого компонента

| Компонент | Обязанность |
|---|---|
| `smart-input-panel.tsx` | Текст, запись, запросы, уточнение, карточки, выбор и подтверждение |
| `smart-input.ts` | Контекст, проверка структуры ответа, перевод намерения в дату/черновик |
| Dev-proxy Vite | Передача `/agent/*` с 4175 на 4176 |
| `server.py` | Приём запросов, лимиты, блокировка параллельной обработки, ASR и ошибки |
| `agent.py` | Проверка входа Pro/Max, промпт, JSON Schema, запуск Claude Code |
| `download.py` | Загрузка закреплённой ревизии Parakeet |
| `benchmark.py` | Замеры локального распознавания аудиофайла |
| `claude-probe.py` | Ранний диагностический пример с двумя предметами; не основной агент |
| `check-identifiers.py` | Живые проверки буквенно-числовых обозначений работ |
| `start.command` | Совместный запуск Python-сервиса и Vite |

### 12.2. Запрос текста

Браузер отправляет `POST /agent/parse`: исходный `text`, `correction`, предыдущие карточки `previousTasks` и `context`. Контекст включает все предметы и правила расписания, якорь, известные сокращения, дату, время, номер дня недели и часовой пояс устройства.

Исключения сейчас передаются как пустой массив с признаком `exceptionsKnown: false`. Это означает отсутствие подтверждённого календаря исключений, а не уверенность, что каникул или переносов нет. Существующие личные задачи целиком модели не передаются.

Claude возвращает массив до 12 предложений. У каждого: `subjectId`, `title`, дословная формулировка срока `deadlineText`, вопрос `question`, объект `deadline` с типом, значением и видом занятия. Поддерживаемые намерения:

| Тип | Значение и обработка |
|---|---|
| `missing` | Срок отсутствует/неясен; требуется дата |
| `date` | Явная полная дата; проверяется как реальная календарная дата |
| `days` | Сегодня/завтра/через N дней; прибавление выполняет код |
| `weekday` | День недели; пока требуется выбрать точную дату |
| `nextLesson` | Следующее занятие нужного предмета и при необходимости вида |

Клиент проверяет обязательные типы полей, количество карточек, непустой текст, допустимый вид и ID предмета. Неизвестный ID превращается в необходимость выбора. Это структурная проверка, **не гарантия сохранения смысла всех слов**.

Для следующей пары агентский код смотрит вперёд менее чем на 60 дней, пропускает уже начавшиеся сегодня занятия и учитывает чётность. Без вида при нескольких видах задаётся вопрос. Если кандидатов одного вида несколько, выбирается ближайший по времени; полноценного выбора между несколькими лабами в агентской карточке пока нет.

### 12.3. Подтверждение и исправление

Пользователь видит исходный текст и редактируемые предмет, название и дату каждой карточки. Можно исключить карточки, написать уточнение и повторить разбор. Поле вопроса блокирует сохранение до явного подтверждения проверки. Выбор даты/предмета вручную сбрасывает прежнюю связь с парой.

Карточки становятся обычными локальными записями только после кнопки добавления. Для ВУЦ получается заметка с предметом. Модель не присваивает постоянные ID и сама ничего не записывает. Окно хранит черновики только до закрытия/перезагрузки.

### 12.4. Голос

Микрофон включается явным действием через `getUserMedia`. `MediaRecorder` выбирает поддерживаемый формат из MP4/WebM. Запись можно остановить или отменить; при закрытии окна дорожки микрофона останавливаются. Автоматическая остановка — около 59 секунд.

`POST /agent/transcribe` передаёт бинарное аудио локальному сервису. Во временной директории ffmpeg декодирует его в моно WAV 16 кГц, затем проверяется длительность. Parakeet возвращает текст. После этого пользователь может исправить расшифровку и отдельно нажать разбор через Claude. Постоянной записи микрофона и потоковой расшифровки нет.

Модель: `mlx-community/parakeet-tdt-0.6b-v3`, ревизия `ed2b7e8c15f9aaa0b5772e2efb986255eaef7e15`. Весовой файл около 2,5 ГБ. Первый запрос загружает модель; последующие используют её в памяти. Временные аудиофайлы удаляются по окончании обработки. Остатки после аварийного завершения отдельным уборщиком не обслуживаются.

### 12.5. Claude и доступ

CLI ищется через `DZ_CLAUDE_BIN`, PATH или установленный Claude Desktop. Нужен вход через `auth login --claudeai`. Код проверяет, что это `claude.ai` с подпиской Pro/Max; API-ключи и альтернативные провайдеры из окружения исключаются.

Используется псевдоним модели `haiku`, то есть конкретная версия за ним не закреплена. CLI запускается с `--safe-mode`, пустым набором инструментов, строгой конфигурацией MCP, без сохранения сессии, с JSON Schema и ограничением числа ходов. Запрос расходует лимиты подписки. Обычная Pro-подписка не объявляется здесь оплаченной квотой платного API.

Сведения об аккаунте, OAuth-коды, токены и ключи в документацию/коммиты не включаются. Вход — локальное состояние компьютера; после клонирования репозитория он не появляется автоматически.

### 12.6. Лимиты и ошибки пилота

| Ограничение | Реализация |
|---|---|
| Текст | до 8000 символов |
| Уточнение в UI | до 2000 символов |
| JSON-запрос | до 200 000 байт |
| Аудиозапрос | до 12 000 000 байт |
| Длительность аудио | до 60 секунд |
| Карточки | от 1 до 12; название до 4000 символов на клиенте |
| Параллельная обработка | один запрос, занятый сервис отвечает 409 |
| ffmpeg | таймаут 20 секунд |
| Claude | таймаут основного запроса 90 секунд |
| Браузерный запрос | отмена по истечении 130 секунд |

Сервис слушает только `127.0.0.1`. Для POST проверяются разрешённый Origin (`localhost`/`127.0.0.1:4175`) и заголовок `X-DZ-Client: local`. Это ограничение локального пилота, не полноценная авторизация публичного сервера. Обычные HTTP-логи отключены, ответы не кешируются.

Ошибки разбора и сети оставляют текст в открытом окне. Отмена браузерного запроса не гарантирует остановку уже запущенного Claude: сервис может оставаться занят до ответа/таймаута. Автоматических бесконечных повторов нет. Некоторые ошибки записи пока отображаются общей фразой — детализация требует доработки.

## 13. Запуск, сборка и публикация

Рабочий каталог — корень репозитория. Основные команды:

```sh
npm ci
npm run dev:design
npm run test:next
npm run build:design
```

Сборка новой версии находится в `dist-design`. Для локального агента после установки зависимостей можно открыть `scripts/voice-local/start.command`, либо запустить отдельно:

```sh
.voice-test.local/venv/bin/python scripts/voice-local/server.py
npm run dev:design
```

Подготовка нового Mac с Python 3.12:

```sh
python3.12 -m venv .voice-test.local/venv
.voice-test.local/venv/bin/pip install -r scripts/voice-local/requirements.txt
.voice-test.local/venv/bin/python scripts/voice-local/download.py
```

Нужен ffmpeg в PATH или `.voice-test.local/bin/ffmpeg`; установленный `imageio-ffmpeg` предоставляет бинарник, путь можно получить через `imageio_ffmpeg.get_ffmpeg_exe()`. Нужны Node 24, npm-зависимости и отдельный вход Claude Code. Launcher умеет использовать Node из bundled runtime Codex на текущем Mac, если обычного Node в PATH нет; это вспомогательный путь, не переносимое требование продукта.

Папка `.voice-test.local/` игнорируется Git: там Python-окружение, кеш модели, путь к модели и локальные результаты. Не коммитить её целиком. Для повторения замера используется `benchmark.py путь-к-аудио --repeat 2`.

В dev: Настройки → Для бета-тестеров → «Текстом или голосом · локальный тест». Для безопасной пробы: `http://127.0.0.1:4175/?demo=1&screen=settings`.

CI получает три ветки: `main` как legacy, `codex/redesign` как прежний Codex-вариант, `codex/rebuild` как текущую версию. Устанавливает зависимости, запускает соответствующие проверки, строит три приложения и собирает каталог `site`: новая версия в корне и `/next/`, прежние в `/legacy/` и `/codex/`.

Workflow запускается при push в эти ветки, но deploy разрешён для `main` и `codex/rebuild`. Только успешный Pages workflow и проверка опубликованных файлов подтверждают выпуск. Push сам по себе не означает, что сайт уже обновился. Сервер агента этим workflow не развёртывается.

## 14. Демо, проверки и правила разработки

`?demo=1` использует примеры в памяти, не читает и не записывает рабочую записную книжку. В обычном демо дата расписания зафиксирована на 21 сентября 2026, время 14:30; `highlight=break` использует 13:35. `clock=live` включает живые часы демо. `fixture=stress`/`empty` меняют набор примеров, `screen=settings|tasks|schedule` задаёт стартовую вкладку.

Агент берёт `new Date()` при запросе независимо от фиксированных часов демо расписания. Следовательно, срок в карточке агента может относиться к реальному сегодняшнему дню, а не к демодате. Демо защищает сохранённые задачи, но само по себе не запрещает реальный запрос в Claude и расход подписки.

Последний зафиксированный набор — 45 прошедших тестов логики. Проверяются хранение, виды заданий, история, группы, недели, интервалы, перерывы, анимационные расчёты и разрешение сроков агента. Живые проверки модели отделены от обычных unit-тестов, потому что требуют входа, сети и лимита подписки.

Проверялись Chromium на мобильных ширинах и компьютере, WebKit и отдельные сценарии iOS Simulator/Device Hub. Эти результаты не заменяют реальный iPhone, его микрофон, клавиатуру и установленную PWA. Часть управления симулятором раньше блокировалась ошибками доступности окна; не считать такую попытку пройденным сценарием.

Для ASR на M1 8 ГиБ получены ориентиры: настоящая запись — 1,74 секунды первый проход и 0,85 повторный, пик памяти MLX около 1,98 ГиБ; первый HTTP-проход — 3,41 секунды. Это отдельные замеры конкретной записи, не гарантированный SLA. У Claude встречались ответы за несколько секунд и таймауты 90 секунд.

Правила работы: русский язык, простой код, изменения только по задаче, сохранение дизайна, расписания, якоря, данных и ярлыка. Новые зависимости оправдывать текущей потребностью. После изменений приложения повысить version в package.json и обеих записях lock-файла, выполнить затронутые проверки, commit/push рабочей ветки и проверить публикацию. Для документации версию приложения не менять. Force-push, удаление старых веток и перезапись чужих правок не входят в обычный выпуск.

Личные локальные материалы, которые нельзя менять или включать в коммит: `docs/ASTRA_WORKFLOW.md`, `docs/SMART_TASK_INPUT_PLAN.md`, `docs/design/concepts/icons-2026-09-27/`. Этот сводный документ пересказывает относящиеся к продукту решения, но не переносит личные переписки, записи, секреты и бэкапы.

## 15. Краткая история решений и изменений

1. Перезапуск начат от Claude-версии `ca43524` (1.20.0) в отдельной ветке; старые версии сохранены. После сравнения концепций выбран A4 «Лист», затем реализована рабочая логика в `design/`.
2. Основные этапы интерфейса, редактора, заметок, тестовых данных и оформления последовательно доведены до рабочей первой версии. Этапы N1–N5 реализованы; полная физическая приёмка N6 остаётся частично открытой. Владелец затем принял основную версию как пригодную и перешёл к агенту.
3. Большая часть повторных замечаний касалась iPhone: системная полоса темы, пустой календарь, дёрганые переходы, слабый отклик кнопок, затемнение пары, клавиатура и вязкость свайпов. Выбранные взаимодействия сохранять; не начинать редизайн заново.
4. В 1.23.53 исправлен разбор CSS-длительностей после минификации `ms → s`, календарные строки и сегментированные переключатели; с разрешения владельца возвращён reload-обход темы iOS. Раньше обход уже существовал, затем его убрали; это не основание откатывать весь проект.
5. 1.23.54–1.23.55 ускорили перелистывание, убрали потускнение календарных кнопок, поправили обрезку номеров недель и движение страниц. `1c3d658` — последняя основа интерфейса до агента.

Исторический инцидент: после одного из обновлений владелец сообщил о пустом экране PWA и самостоятельно переустановил приложение. Точная причина и сохранность старых задач не были подтверждены. Не выдавать это за найденную и окончательно исправленную нами причину.

## 16. Текущее состояние и дальнейший план

### 16.1. Что уже можно использовать

Обычное опубликованное приложение: расписание, ручные ДЗ и заметки, выполнение/история, локальное хранение, экспорт, темы и офлайн-оболочка. Локальный агент: текст/аудио → предложения → ручная проверка → локальное сохранение. Последняя подтверждённая публикация к моменту составления — 1.23.57; в рамках этого документа повторная функциональная приёмка приложения не проводилась.

### 16.2. Что пока не готово или требует проверки

- Нет соединения опубликованного iPhone-приложения с агентом на Mac. Нет публичной серверной авторизации, HTTPS-endpoint и серверного развёртывания.
- Качество извлечения не гарантировано: фактически терялись слова и части идентификаторов. Промпт усилен, но нужна дальнейшая регрессия и понятная проверка спорных мест.
- Нет подтверждённого календаря каникул, переносов и весеннего семестра. Сброс учебных недель в конце января нельзя назначить произвольно.
- Агентская карточка не даёт полноценного выбора конкретной пары; ручная смена даты/предмета снимает связь. Заметки, включая ВУЦ, сейчас не вложены в пару. Более ранний запрос владельца на явную привязку таких записей остаётся отдельной доработкой.
- Реальные микрофон, Safari/standalone, отказы доступа, шум и тишина, длинные диктовки и поворот экрана не покрыты полной приёмкой. Одно успешное распознавание файла её не заменяет.
- Остались физические проверки интерфейса: VoiceOver, клавиатура, старый ярлык после обновления, системные области тем, разные размеры iPhone и реальная частота экрана. После принятия интерфейса повторять только затронутые сценарии.
- Нет импорта JSON, синхронизации, общей базы, редактирования расписания через текущий интерфейс, библиотеки материалов и постоянной памяти агента.

### 16.3. Порядок продолжения агента

1. **Надёжность содержания.** Собрать небольшой постоянный набор реальных фраз: ВУЦ, коды работ, номера/страницы, самоисправления, несколько предметов и сроков. Проверять смысл и полноту, а не литературную формулировку. При неуверенности сохранять исходные слова и уточнять.
2. **Сроки и связи.** Понятно предлагать варианты для дня недели и следующего занятия, выбирать конкретную пару при неоднозначности; показывать абсолютную дату. Проверить полночь, Новый год и часовой пояс. Существующие дедлайны не переносить.
3. **Уточнения.** Проверить цепочки исправлений и ручные изменения карточек: последняя правка имеет приоритет, остальные детали не исчезают. Нужен контекст текущего диалога, не память обо всей переписке владельца.
4. **Голос и ошибки.** Проверить реальный микрофон, разные форматы Safari, паузы/шум/тишину, отмену, недоступный Mac и лимит Claude. Сохранять введённый текст при ошибках, не создавать задания молча, не обещать отмену внешнего запроса только по закрытию окна.
5. **Связь телефона с Mac.** Выбрать защищённый способ доступа с HTTPS и авторизацией, согласовать адрес и запуск. Не открывать существующий loopback-сервис в интернет простым изменением bind. Покупка хостинга и платного API не одобрена как текущий способ реализации.
6. **Обычный вход в приложении.** После рабочей связи и приёмки перенести запуск из dev-бета-раздела в удобное добавление «Написать / Надиктовать», сохранив быстрый ручной ввод, три вкладки и выбранный вид.
7. **Приёмка и выпуск.** Подтвердить путь от реальной диктовки на iPhone до единственного сохранения выбранных карточек; проверить ошибки, обновление и независимость ручного ввода. Только после этого считать телефонную функцию готовой.

Соответствие прежним этапам: S0 — локальная основа выбрана и измерена; S1/S2/S3 — реализован локальный текстовый путь с карточками и сохранением; S4 — код голоса и распознавание файла есть, приёмка устройств неполная; S5 — защищённое подключение и телефонный выпуск ещё впереди. Старые таблицы «всё не начато» относятся к дате их написания и не отражают нынешний пилот.

### 16.4. Отложенные направления

Импорт и восстановление JSON, редактирование предметов/расписания, облачные копии, синхронизация друзей и общая база — отдельные задачи. Материалы, PDF, фотографии тетрадей, поиск по учебникам, конспекты, озвучивание и постоянное прослушивание не входят в первую версию агента. Агент пока не должен самостоятельно удалять/изменять старые задачи, решать задания или выполнять команды на компьютере.

## 17. Как пользоваться этим документом

Это единая обзорная точка входа для владельца и следующего разработчика. При расхождении приоритет имеют новые указания владельца и фактический текущий код. Перед правками сверять Git: документ фиксирует срез, а не автоматически обновляемое состояние.

Исходные документы остаются на месте: `AGENTS.md` — правила; `CURRENT_HANDOFF.md` — последние передачи; `AGENT_LOCAL_PILOT.md` и `scripts/voice-local/README.md` — пилот; `UI_NEXT_PLAN.md`, `IPHONE_FIX_PLAN.md`, `IOS_POLISH_PLAN.md`, `REBUILD_PLAN.md` — контекст этапов. Отчёты реализации находятся в `docs/design/implementation/`. Старые README могут содержать уже неверные утверждения, например об отсутствии офлайна или о том, что агент ещё не начат; этот обзор сверялся с кодом 1.23.57.

Секреты, личные аудиозаписи, переписки, содержимое рабочего localStorage и кеши моделей намеренно не включены. Документ описывает систему, не является резервной копией пользовательских заданий.
