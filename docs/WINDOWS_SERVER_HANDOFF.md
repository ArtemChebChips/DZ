# Тестовый сервер ДЗ на Windows: передача новому чату

Владелец хочет сначала использовать свой Windows-компьютер вместо VPS.
Это документ для агента, работающего **на том Windows-компьютере с доступом
к терминалу и файлам**. Настройка Windows в текущем чате на Mac не выполнялась.

## Готовая основа

- Репозиторий: `https://github.com/ArtemChebChips/DZ.git`.
- Нужная ветка: `codex/agent-sync`, версия приложения 1.24.0.
- Реализация: `609096c`, дополнение отчёта: `14019a0`; данный документ добавлен позже.
- Прочитать `AGENTS.md`, относящиеся к серверу части `CLAUDE.md`,
  `docs/AGENT_SYNC_PLAN.md`, `docs/AGENT_SYNC_REPORT.md`, `server/README.md`.
- Использовать существующий сервер и голосовой пилот, не писать их заново.
  Python/SQLite, Parakeet v3 INT8 через sherpa-onnx CPU, ffmpeg,
  Claude Code `haiku` через подписку Pro/Max.
- Windows/WSL, внешний HTTPS и физический iPhone ещё не проверены.
  Напрямую в Windows есть непереносимые части: например, рабочий каталог `/tmp`
  в `scripts/voice-local/agent.py` и Linux service-конфигурация. Для начала выбрать WSL2.

## Рекомендуемый тестовый вариант

**Windows → WSL2/Ubuntu → сервер ДЗ. Windows и iPhone → одна сеть Tailscale.**

WSL2 позволяет запускать Linux на Windows без переустановки основной системы.
Для установки может понадобиться окно администратора и перезагрузка; агент должен
проверить существующие дистрибутивы и не переустанавливать их с удалением данных.
Предпочтительна Ubuntu 24.04 с Python 3.12, но сначала проверить доступность/текущую установку.

Tailscale Serve предоставляет HTTPS-адрес только устройствам своей сети.
Публичный IP и проброс портов на роутере для такого теста не нужны.
На iPhone потребуется установленный и подключённый Tailscale. Проверить совместимость
с уже используемым VPN; не менять его настройки молча. Для личного использования
есть бесплатный тариф. Условия и установщики сверить с официальными источниками.

Сначала CPU; настройка CUDA и видеокарты не нужна для существующего варианта.
Выделить WSL достаточно памяти и измерить фактическую скорость на этом компьютере.
Замеры Mac из отчёта не являются замерами Windows.

## Задание агенту на Windows

1. Проверить Windows, архитектуру процессора, память, установленный WSL2,
   свободные порты и существующие проекты/службы. Работать в отдельной папке/checkout
   ветки `codex/agent-sync`; чужие рабочие деревья не переключать. До изменений
   сохранить существующие конфигурации и базы, если они обнаружатся.
2. Установить недостающие WSL/Ubuntu, Python venv, ffmpeg, Git, Node 24 для сборки
   клиента и Claude Code из официальных источников. Код/venv желательно хранить
   в Linux-файловой системе WSL, не переносить `node_modules` с Mac.
3. Создать отдельный каталог постоянных данных вне checkout, указать `DZ_DATABASE`,
   `DZ_ASR_MODEL`, `DZ_CLAUDE_BIN`. Установить `server/requirements.txt` в venv и
   скачать модель через `server/download_model.py`.
4. Попросить владельца выполнить вход Claude Pro/Max от того Linux-пользователя,
   который будет запускать сервер. Не копировать OAuth-токены из переписки/Mac,
   не переключать незаметно на платный API. Проверить реальный `haiku` через
   существующий `agent.py`, доступность региона и лимиты.
5. Создать личный аккаунт командой `server/app.py create-user`: скрытый ввод пароля,
   без аргументов командной строки. Поднять API на свободном loopback-порту
   (обычно 4286). Сохранить базу при остановке/обновлении, настроить отдельные backup-файлы.
6. Установить Tailscale на Windows; владелец выполняет вход и подключает iPhone
   к своей сети. Настроить **Serve** и HTTPS для личного теста. Публичное размещение
   через Funnel или иной туннель не включать автоматически.
7. Для телефона нужна также **клиентская сборка этой ветки**. Действующий сайт
   GitHub Pages не содержит изменения `codex/agent-sync`. Не объединять и не
   публиковать её автоматически: собрать `design/` и показать через частный HTTPS.
   Простой вариант — Caddy внутри WSL на свободном loopback-порту: `/api/*` проксирует
   API без удаления префикса `/api`, остальные пути отдают `dist-design`.
   Tailscale Serve на Windows направляет запросы к этому локальному входу.
   Проверить localhost-доступ Windows → WSL прежде, чем соединять всю цепочку.
8. В `DZ_ALLOWED_ORIGINS` указать точный HTTPS-origin тестового приложения.
   Привязать аккаунт к стабильному адресу сервера. HTTPS-адрес Serve фиксировать
   в инструкции для владельца; избегать временных меняющихся адресов для рабочих
   данных: в клиенте привязка учитывает URL сервера, прежняя очередь не переносится
   молча на новый URL.
9. **Другой origin — другое localStorage.** До телефонного теста владелец скачивает
   JSON из действующего приложения. Тестовая страница не прочитает его записи сама.
   Импортировать копию существующим интерфейсом, проверить её, затем привязать аккаунт.
   Не очищать данные старого ярлыка и не выдавать пустую тестовую страницу за потерю записей.
10. Проверить серверные тесты, `test:next`, сборку, вход, две копии клиента, офлайн
    и повторную отправку, конфликты/удаления, выход без удаления данных, backup.
    На физическом iPhone проверить HTTPS, разрешение микрофона, запись → Parakeet →
    Claude → карточки → сохранение/отмена, в Safari и установленной PWA.
    Провести тест с обозначением «Э-104» и номерами: ASR ранее ошибалась в них.
    Автоматическое добавление по умолчанию оставить выключенным.
11. Для первого теста можно держать сервер в открытом терминале Ubuntu.
    Затем подготовить запуск после перезагрузки Windows и восстановление после сбоя.
    Один установленный systemd unit внутри WSL ещё не доказывает Windows-автозапуск:
    проверить фактическую перезагрузку и доступ с iPhone.
    Согласовать отключение сна на время сервера; выключенный/спящий ПК недоступен.
12. В конце выдать владельцу HTTPS-ссылку, инструкции запуска/остановки,
    местонахождение базы/копий и фактический отчёт проверок. При изменении кода
    соблюдать AGENTS.md: версия/lock, проверки, commit/push своей рабочей ветки,
    без объединения и автоматической публикации.

Обычный текстовый чат в браузере не заменяет доступ агента к локальному терминалу.
Использовать локальный чат Codex/ChatGPT desktop с выбранной папкой проекта либо
Codex CLI. Входы в аккаунты и некоторые действия Windows потребуют участия владельца.

## Короткий запрос для нового чата

> Разверни тестовый сервер моего приложения «ДЗ» на этом Windows-компьютере.
> Репозиторий https://github.com/ArtemChebChips/DZ.git, ветка codex/agent-sync.
> Сначала прочитай docs/WINDOWS_SERVER_HANDOFF.md и выполняй его шаги.
> Используй существующий код через WSL2/Ubuntu, Parakeet v3 на CPU, мой Claude Pro
> и Tailscale Serve для частного HTTPS-доступа с iPhone. Подними также тестовую
> клиентскую сборку этой ветки. Сохрани данные, не мешай другим агентам,
> не объединяй ветки и не публикуй GitHub Pages. Доведи до проверки на телефоне;
> сообщай, когда нужен мой вход, перезагрузка или другое действие на компьютере.
