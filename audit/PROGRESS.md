Концепции/отчёты, старая реализация и личные материалы учитываются отдельными группами и не считаются текущим runtime.

Программный аудит актуального снимка и исправления завершены. Версия **1.23.58**, ветка **`codex/audit`**. Все текущие собственные исходники просмотрены с учётом связей; пофайловый журнал и его проверка — `COVERAGE.md`, `coverage.json`, `scripts/check-audit-coverage.mjs`. Сводка исправлений и открытых пунктов — `FINDINGS.md`; детали — `DATA.md`, `PWA.md`, `UI.md`, `TESTS.md`, `VOICE.md`.

Итоговая проверка замороженной сборки:

- **56/56** проверок логики, **28/28** браузерных сценариев без пропусков (27 production и один DEV mock-пилота).
- Два окна: **20 раундов, все 40 записей**; очередь, двойная отправка/удаление, отказ записи, конфликт и новые черновики проверены.
- PWA: все шесть сценариев обновления/изоляции/холодного запуска проходят. При искусственной задержке сети 8000 мс: **3602–3607 мс → 69–85 мс** в Chrome на Mac. После полного перезапуска Chrome: 84 мс с медленной сетью, 94 мс офлайн. Эти цифры относятся к условию теста и не являются измерением iPhone.
- Воспроизводимые Python mock-проверки: **26 успешных, четыре expected failures** для трёх групп остающихся ошибок локального пилота. Их статус открыт, не «исправлено».
- TypeScript основной и design-конфигураций, production-сборка, diff-check проходят. Актуальный npm audit — **0 найденных уязвимостей**, результат сохранён в `dependencies.json`.
- Восемь снимков мобильной/компьютерной вёрстки просмотрены. Нагрузка 1000 синтетических заданий сохраняет все записи; время локального переключения и число DOM-узлов находятся в `browser-stress.json`. Без утверждений о реальном fps телефона.

Однократный отказ timing assertion исходной PWA в общем тестовом сервере не воспроизведён. Harness добавил отдельные origin/монотонные часы/диагностику; два последовательных изолированных прогона прошли. Причина первого отказа неизвестна, это не скрывается и не выдается за исправленный production-баг.

## Продолжение и физическая приёмка

Версия 1.23.58 опубликована по прямой просьбе владельца: коммит `7ecf603` отправлен в `codex/rebuild`, [Pages run 36902601849](https://github.com/ArtemChebChips/DZ/actions/runs/36902601849) завершился успешно. Номер версии и офлайн-загрузка проверены по живым адресам корня и `/next/`; владелец подтвердил обновление на телефоне. Параллельная ветка агента/сервера не объединялась. Перед будущим объединением с ней особое внимание `main.tsx`, асинхронному `notebook.update`, сохранению пакета панели и номеру package/lock. Все записи в notebook должны использовать один новый протокол блокировки. После объединения повторить команды из `TESTS.md`/`PWA.md`/`VOICE.md` и проверку хешей; изменённые файлы сначала заново изучить, а не молча обновлять ledger.

На настоящем iPhone после публикации проверять именно новую видимую версию:

1. Открыть установленный ярлык, дождаться установки worker; проверить существующие задания и сохранение новой записи. Перезапустить прежние открытые окна для использования исправленного протокола.
2. Полностью выгрузить приложение и открыть несколько раз с обычной сетью, медленной сетью и без сети. Первый в жизни запуск без установленного кеша не относится к офлайн-приёмке.
3. Проверить возврат из фона, переход через полночь, смену месяца/дня и текущую подсветку реальных пар.
4. Проверить диагональные/повторные свайпы, длинный список, уменьшение движения, клавиатуру и видимость сохранения в портретном/альбомном режиме.
5. Проверить все темы в standalone: штатный reload настроек и сохранность заданий; новый черновик во время задержанной записи темы не должен теряться.
6. Оставить введённый несохранённый текст во время фонового обновления версии: worker не должен сам перезагружать форму. Проверить последующий холодный запуск.

Ошибки Python-пилота и замечания записи микрофона передать в параллельный чат по `VOICE.md`; реальный Claude/ASR/микрофон/подключение сервера не подменяются этими mock-проверками. Старые успешные PWA-кеши не удалять без учёта версий открытых клиентов.
