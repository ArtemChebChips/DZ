## Краткое описание продукта

Мобильное веб-приложение (PWA) для студента российского технического вуза (МГТУ им. Баумана),
где расписание двухнедельное: неделя-«числитель» и неделя-«знаменатель» различаются по составу
пар. Часть предметов идёт раз в две недели.

Задача приложения: записывать домашние задания на конкретные пары и видеть их списком по
дедлайнам, не считая в уме, когда будет следующее занятие по предмету.

Живёт на GitHub Pages, ставится на домашний экран iPhone, данные хранит только на устройстве.

- Репозиторий: https://github.com/ArtemChebChips/DZ (public)
- Рабочий сайт: https://artemchebchips.github.io/DZ/

## 1. Суть приложения и границы MVP

### Для кого и зачем

Один пользователь — студент, перешедший на новый курс. Его слова: домашних заданий много, они
не запоминаются, записи на бумаге превращаются в кашу именно из-за чередования недель.
`[требование]`

Ключевая проблема, ради которой всё делалось: «сдать к следующей паре» для предмета раз в две
недели означает то через неделю, то через две. Считать это вручную каждый раз — источник
ошибок. `[требование]`

### Основные сценарии

1. Открыть день в календаре → увидеть пары этого дня → записать задание прямо на плашку пары.
2. Открыть главный экран → увидеть все несделанные задания по возрастанию дедлайна.
3. Отметить задание выполненным.
4. Поправить расписание, если что-то изменилось.

### Обязательное поведение (сохранить при любой переделке)

- `[требование]` Расписание с числителем/знаменателем; пары бывают «каждую неделю»,
  «только числитель», «только знаменатель».
- `[требование]` Экран дня показывает пары именно этого дня с учётом чётности недели.
- `[требование]` Задание записывается на конкретный предмет и конкретный день.
- `[требование]` Главный экран: задания по возрастанию дедлайна, сгруппированные
  «Просрочено → Эта неделя → Следующая неделя → Больше недели», внутри группы — по дням.
- `[требование]` Срок до сдачи должен быть виден крупно, а не мелким серым шрифтом.
- `[требование]` При добавлении задания с плашки пары предмет уже выбран, выбирать его повторно
  не нужно, а дата по умолчанию — тот день, который открыт.
- `[требование]` Данные хранятся на устройстве, без регистрации.
- `[требование]` Работает на iPhone как приложение с домашнего экрана. Android — тоже

- `[требование]` Тумблер ночной темы и тумблер «Режим сдвгшника» в настройках.

## 3. Точные правила расписания

Вся логика — `src/lib/week.ts`. Экраны её не дублируют. `[код]`

### 3.1. Числитель и знаменатель

Это две учебные недели, чередующиеся через одну. В коде — тип
`Parity = 'num' | 'denom'`, где `num` = числитель, `denom` = знаменатель.

**Важно: календарный номер недели (ISO week) не используется вообще.** Чётность считается от
якоря:

```ts
export function parityOf(iso: string, anchorMonday: string): Parity {
  const weeks = Math.round(diffDays(anchorMonday, mondayOf(iso)) / 7)
  const even = (((weeks % 2) + 2) % 2) === 0
  return even ? 'num' : 'denom'
}
```

- `anchorMonday` — понедельник недели, которая заведомо числитель. Хранится в
  `settings.anchorMonday`.
- Чётное число недель от якоря → числитель, нечётное → знаменатель.
- Остаток нормализуется, поэтому даты **до** якоря считаются правильно. `[проверено]`
- Переходы через месяц и год отдельного кода не требуют: считается разница в днях между
  понедельниками. Проверено на паре 29.12.2025 → 05.01.2026: чередование не сбилось.
  `[проверено]`

Текущее значение якоря: **`2026-08-31`** (`ANCHOR_MONDAY` в `src/data/schedule.ts`).
Основание — слова владельца: учебный год всегда начинается с числителя, а неделя
31 августа — 6 сентября 2026 была числителем. `[требование]`

### 3.2. Начало недели и дни

- Неделя начинается **с понедельника**: `weekdayOf()` возвращает 1 для понедельника и 7 для
  воскресенья, `mondayOf()` откатывает дату к понедельнику её недели.
- Тип `Weekday = 1 | 2 | 3 | 4 | 5 | 6` — воскресенья в расписании не бывает,
  `lessonsOn()` для воскресенья всегда возвращает пустой массив. `[код]`

### 3.3. Даты и часовой пояс

Даты хранятся как строки `'YYYY-MM-DD'` и трактуются как **локальные** календарные даты.
Часовой пояс нигде не задаётся и не используется. `src/lib/dates.ts` намеренно парсит строку
вручную:

```ts
export function parseISO(iso: string): Date {
  const [y, m, d] = iso.split('-').map(Number)
  return new Date(y, m - 1, d)   // локальная полночь
}
```

Причина: `new Date('2026-09-06')` парсится как UTC и в отрицательных поясах уезжает на день
назад. `[решение AI]`

Отметки времени (`createdAt`, `updatedAt`, `doneAt`) — наоборот, полные ISO-строки UTC
(`new Date().toISOString()`), для отображения не используются.

### 3.4. Модель пары

```ts
type WeekParity = 'num' | 'denom' | 'both'
type LessonKind = 'lecture' | 'seminar' | 'lab' | 'other'

type Lesson = {
  id: string
  subjectId: string
  weekday: Weekday        // 1..6, пн..сб
  start: string           // 'HH:MM', по нему же сортировка внутри дня
  end: string
  parity: WeekParity
  room?: string           // '301х' или 'каф. ФН4'
  building?: string       // 'В1 ХимЛаб'
  teacher?: string        // преподаватель у пары, а не у предмета
  kind: LessonKind
  updatedAt: string
}
```

Важные особенности:

- **Времени у пары своё**, общей сетки звонков нет. Это прямое требование: в расписании
  занятия начинаются в 08:30, 09:50, 10:10, 11:50, 12:25, 14:05, 15:55, 17:35, 18:00.
  `[требование]` В версии 1 данных была общая сетка `settings.slotTimes` — удалена.
- **Преподаватель принадлежит паре, а не предмету.** У «Физики и естествознания» лекцию ведёт
  один человек, лабораторные — двое других, семинар — четвёртый. `[код]`
- `parity: 'both'` — пара идёт каждую неделю.
- Один предмет может встречаться в дне несколько раз (в текущих данных — Материаловедение по
  средам двумя лабораторными подряд).
- Один и тот же предмет в одно время может иметь **разные аудитории** для числителя и
  знаменателя. Это заведено двумя отдельными записями (Инновации по вторникам: 532к в
  числитель, 535к в знаменатель). `[код]`

### 3.5. Чего нет

- Исключений, переносов, отменённых пар, праздников — **не реализовано**. `[код]`
  Единственный инструмент против сдвигов — перенос якоря, который смещает чередование целиком.
- Дат начала и конца семестра нет: расписание считается бесконечным в обе стороны.
- Сессия, зачётная неделя — не моделируются.

### 3.6. Влияние редактирования расписания на задания

Связь только через `subjectId`. Задание **не ссылается** на конкретную пару, поэтому:

- изменение времени, дня, чётности или аудитории пары на существующие задания не влияет —
  их `due` остаётся прежним; `[код]`
- удаление пары не трогает задания; задание просто перестанет показываться внутри плашки и
  переедет в блок «Сдать в этот день»;
- **удаление предмета удаляет и его пары, и все его задания** (`deleteSubject` в
  `src/store.ts`), пользователь предупреждается количеством. `[код]`

и в календаре.

### 4.2. Как определяется дедлайн

Подстановка живёт в `TaskEditor` и опирается на `nextLessonDates()` из `src/lib/week.ts`.
Функция шагает по дням вперёд (горизонт 60 дней), пропускает воскресенья и для каждой даты
проверяет, есть ли у предмета пара с подходящей чётностью. Именно это даёт корректный ответ
для предметов раз в две недели. `[код]` `[проверено]`

Поведение зависит от того, откуда открыт редактор:

| Откуда открыт | Дата по умолчанию | Пресеты |
|---|---|---|
| Плашка пары или «+» на экране дня (`fromDate` задан) | **сам этот день** | «В этот день», «Следующая пара» |
| Кнопка «+» на главном экране (`fromDate` нет) | первая следующая пара по предмету | «Следующая пара», «Через одну» |

Изначально дата всегда подставлялась как «следующая пара», но владелец указал, что это
неверно: открыв конкретный день, он записывает задание **на него**. Исправлено.
`[требование]` `[проверено]`

Дату всегда можно задать вручную полем `type="date"`; после ручного ввода автоподстановка
для этого сеанса отключается (флаг `dueTouched`).

Если у предмета в расписании нет ни одной пары, пресеты не показываются, вместо них текст
«У этого предмета нет пар в расписании — выбери дату вручную», а дата по умолчанию —
`fromDate` либо сегодня. `[код]`

### 4.3. Группировка и сортировка

`buildBuckets()` в `src/screens/TasksScreen.tsx`:

```ts
const today = todayISO()
const thisWeekStart = weekdayOf(today) === 7 ? addDays(today, 1) : today
const thisWeekEnd = addDays(mondayOf(thisWeekStart), 6)
const nextWeekEnd = addDays(thisWeekEnd, 7)
```

- `due < today` → **Просрочено**
- `due <= thisWeekEnd` → **Эта неделя**
- `due <= nextWeekEnd` → **Следующая неделя**
- иначе → **Больше недели**

В воскресенье «этой неделей» считается уже та, что начинается в понедельник — иначе блок
всегда пустой. Это допущение согласовано с владельцем. `[требование]`

Сортировка: сначала по `due` (лексикографически, что для `YYYY-MM-DD` совпадает с
хронологией), при равных датах — по `createdAt`, то есть в порядке добавления. `[код]`
Задания без времени, поэтому внутри дня порядок только по времени создания.

### 4.4. Выполнение, редактирование, удаление

- `toggleTask()` переключает `done` и проставляет/снимает `doneAt`. Выполненное исчезает из
  блоков недель и попадает в свёрнутый список «Выполненные». Восстановление — повторный тап.
- Редактирование: тап по заданию → та же панель, можно менять предмет, текст, заметку и дату.
- Удаление: кнопка с корзиной в панели редактирования, **без подтверждения**. `[код]`
  Это потенциально неприятно; см. раздел 9.

`[проверено]`

**Пример 2 — переход между типами недель.**

От 07.09 ближайшие занятия: **09.09** (ср, знаменатель), **19.09** (сб, числитель),

**Пример 3 — открытие конкретного дня.**

## 5. Данные и их сохранность

### 5.1. Структуры

```ts
type Subject = {
  id: string
  name: string
  short?: string     // короткое имя для узких мест
  color: string      // ключ палитры: 'blue' | 'violet' | ... | 'slate'
  updatedAt: string
}

type Settings = {
  anchorMonday: string   // 'YYYY-MM-DD', понедельник недели-числителя
}

type AppData = {
  version: number
  subjects: Subject[]
  lessons: Lesson[]
  tasks: Task[]
  settings: Settings
}
```

Связи: `Lesson.subjectId → Subject.id`, `Task.subjectId → Subject.id`. Прямой связи
задание ↔ пара нет.

Определения: `src/types.ts`. Цвет хранится ключом, а конкретное значение подставляется
CSS-переменной `--subj-<ключ>` — чтобы цвета менялись вместе с темой (`src/lib/palette.ts`).

### 5.2. Хранение

- Всё лежит в `localStorage` под ключом **`dz:data`** одним JSON-объектом. `src/store.ts`.
- Выбранная тема — отдельный ключ **`dz:theme`** (`src/lib/theme.ts`).
- Идентификатор устройства — **`dz:device`**, генерируется один раз, попадает в `Task.authorId`.
  Сейчас нигде не используется, это задел под общую базу. `[код]`
- Состояние в React раздаётся через `useSyncExternalStore`, без внешних библиотек.

Сервера, аккаунтов и синхронизации между устройствами **нет**. `[код]` Данные на компьютере и
на телефоне независимы: это отдельно проговаривалось с владельцем.

### 5.3. Жизненный цикл

- **Перезапуск приложения** — данные читаются из `localStorage`. `[проверено]`
- **Первый запуск / очистка данных браузера** — `freshData()` выдаёт расписание и предметы по
  умолчанию, список заданий пуст.
- **Обновление приложения** — данные не трогаются, срабатывает `normalize()`.
- **Ошибка записи** (приватный режим, переполнение квоты) — проглатывается, приложение
  продолжает работать в памяти до закрытия. `[код]`

### 5.4. Миграции

`DATA_VERSION = 2`. Единственная реализованная миграция: в версии 1 у пары был номер слота
(`slot`), а время лежало в общей сетке `settings.slotTimes`. Такие записи распознаются по
отсутствию строкового `start`; тогда расписание и предметы берутся заново из умолчаний,
**задания сохраняются**. Результат сразу записывается обратно. `[код]` `[проверено]` —
проверялось подсовыванием данных версии 1: версия стала 2, встали 28 пар, задание уцелело.

### 5.5. Экспорт и импорт

Настройки → «Резервная копия»: «Выгрузить» скачивает весь `AppData` как
`dz-backup-YYYY-MM-DD.json`, «Загрузить» читает файл и заменяет состояние целиком через тот же
`normalize()`. Это же — единственный способ перенести данные между устройствами.
`[проверено]` — экспорт, очистка, импорт, 6 заданий вернулись.

## 7. Дизайн и предпочтения владельца

### 7.1. Что было отвергнуто и почему

- **Стиль Apple** отвергнут заранее: «стиль Apple все выбирают, как-то не очень хочется».
  `[требование]`
- Из первой подборки (Тетрадь / Необрутализм / Журнальный / Мягкий) выбраны **второй и
  четвёртый**. Тетрадь и Журнальный отклонены без комментария.
- Из второй подборки вариаций мягкого (Тихий / Воздух / Ночной мягкий / Стикеры) выбраны
  **Тихий и Ночной мягкий**. `[требование]`

### 7.2. Что владелец потребовал явно

- Основная тема — «Тихий»; «Ночной мягкий» включается тумблером в настройках.
- Необрутализм остаётся отдельным режимом под названием **«Режим сдвгшника»** (формулировка
  владельца, сохранена дословно).
- Срок до сдачи — крупнее, без мелкого серого шрифта.
- Иерархия на главном экране: прямоугольник недели → внутри тонкая полоса дня → внутри
  скруглённые «овальчики» задач. Цитата: «есть большой прямоугольник, который обозначает
  неделю, и внутри него уже там по дням».

### 7.3. Текущий интерфейс

Три темы, переключаются атрибутом `data-theme` на `<html>`:

| | Тихий (по умолчанию) | Ночной мягкий | Режим сдвгшника |
|---|---|---|---|
| Фон | `#e9ebee` | `#14161d` | `#f7ee5e` |
| Карточка | `#ffffff` | `#1d2029` | `#fffdf2` |
| Акцент | `#3f6fb5` | `#7aa2f7` | `#12100b` |
| Скругление карточки | 18px | 20px | 4px |
| Рамка | 1px | нет | 2.5px чёрная |
| Тень | нет | нет | `4px 4px 0` |
| Заголовки | Onest | Onest | Unbounded, капсом |

Механика: токены Tailwind в `@theme` ссылаются на обычные CSS-переменные, а те
переопределяются в блоках `:root[data-theme="..."]`. Поэтому разметка у всех тем общая, а
тема — это смена одного атрибута. Цвета предметов тоже переменные (`--subj-*`): в ночной теме
они светлее, иначе тонут в фоне. `[решение AI]`

Шрифты: **Onest** (основной), **Unbounded** (заголовки только в режиме сдвгшника), оба с
Google Fonts. Семантические классы `.card`, `.pill`, `.card-late`, `.display` в
`src/index.css` — единственное место, где темы расходятся по форме, а не по цвету.

### 7.4. Что можно переосмыслить свободно

Всё визуальное. В частности:

- конкретные оттенки, скругления, тени, шрифты;
- нижняя навигация из трёх вкладок (владелец её не заказывал);

- панель снизу как способ показать редактор;

- сама идея «три темы» — требование было про два тумблера, а не про архитектуру тем.

Не трогать без согласования: состав и порядок групп на главном экране, иерархию

### 9.2. Известные проблемы и техдолг

Мешает основному сценарию:

1. **Нет подтверждения при удалении задания** — кнопка-корзина в редакторе срабатывает сразу.
   Промах пальцем = потеря записи.
2. **Обновление приложения требует полного перезапуска** — нет уведомления о новой версии.
   Владелец уже сталкивался с тем, что правка «не приехала».

Важно поправить для MVP:

3. **`theme_color` и `background_color` в манифесте — от старой тёмной темы** (`#0f1115`).
   Splash-screen на iPhone, вероятно, не соответствует светлой теме.
4. **`.safe-bottom` теперь нулевой глобально**, а этот же класс используется у выезжающей
   панели (`Sheet` в `src/components/ui.tsx`). Значит нижний отступ пропал и у панели
   редактирования — на устройстве не проверялось, но кнопка «Добавить» может оказаться вплотную
   к краю экрана.
5. **Офлайн на iPhone не подтверждён** — надо просто проверить в авиарежиме.

Можно отложить:

6. Иконки приложения в стиле старой тёмной темы.
7. `tsconfig.tsbuildinfo` закоммичен — артефакт сборки в репозитории, надо в `.gitignore`.
8. Мёртвый код: `parityOfLessonLabel` и `nextLessonDate` в `src/lib/week.ts`,
   `replaceSchedule` в `src/store.ts` — экспортируются, но нигде не вызываются.
9. README местами устарел: описывает блок «Чётность недели» в настройках и кнопку «Текущая
   неделя — числитель», хотя они переехали на экран «Расписание» и кнопка называется
   «сдвинуть».
10. Автоматическое короткое имя предмета берёт первое слово названия, что для «Основы теории
    вероятностей…» даст «Основы». Правится вручную в «Предметах».
11. Нет перехода из задания на экран его дня.

### 9.3. Решения и их причины

- **PWA вместо нативного iOS** — разработка ведётся на Windows, нативная сборка требует Mac,
  Xcode и платного аккаунта Apple. Плюс тот же код работает на Android. `[решение AI]`,
  согласовано.
- **Якорь чётности вместо «даты начала семестра»** — переживает каникулы и переносы, чинится
  одним нажатием. `[решение AI]`
- **Даты как строки, разбираемые вручную** — `new Date('YYYY-MM-DD')` парсится как UTC и в
  отрицательных поясах уезжает на день назад.
- **Время у пары, а не общая сетка звонков** — прямое требование владельца, в его расписании
  единой сетки нет.
- **Преподаватель у пары, а не у предмета** — в реальных данных у одного предмета разные
  преподаватели на лекции, лабораторной и семинаре.
- **Хранение в `localStorage`, а не IndexedDB** — данных мало (десятки записей), синхронный
  API проще. Заметки с фотографиями изменили бы этот выбор.

### 9.4. Что уже оказалось неудачным

- **Базовые стили для `button` вне CSS-слоёв.** Правило `button { color: inherit }` вне
  `@layer` перебивает все цветовые утилиты Tailwind, потому что неслоёные стили выигрывают у
  слоёных. Симптом был неочевидный: чекбоксы выглядели уже отмеченными, активная вкладка не
  подсвечивалась. Лечится обёрткой в `@layer base`. Если новый дизайн будет на Tailwind v4 —
  эти грабли стоит помнить.
- **Первая версия редактора задания открывалась одинаково отовсюду** — с плашки пары
  предлагала заново выбрать предмет и ставила дедлайн на следующую пару вместо открытого дня.
  Владелец отдельно на это указал.
- **Общая сетка звонков в настройках** — не подошла реальному расписанию, удалена вместе с
  типом `Settings.slotTimes`.
- Попытки записывать большие файлы кода через heredoc в Bash обрывались на длинных строках —
  на процесс разработки это влияло, на результат нет.

Сценарии, по которым проверяется, что функциональность сохранена. Даты соответствуют текущему
якорю `2026-08-31`.

1. **Числитель.** Открыть 14.09.2026 — день помечен как числитель; видны Физика-лекция 14:05
   и две лабораторные по физике 15:55 и 17:35 на каф. ФН4; Материаловедения нет.
2. **Знаменатель.** Открыть 07.09.2026 — знаменатель; видны Материаловедение 11:50 (301х),
   Физика-лекция 14:05, Физика-семинар 15:55 (523); лабораторных нет.
3. **Переход между неделями.** Открыть 13.09 и 14.09 подряд — чётность меняется со
   знаменателя на числитель. Проверить также 29.12.2025 и 05.01.2026: чередование не сбивается
   через год.
4. **Дедлайн раз в две недели.** Создать задание по «Информационным технологиям» 07.09 с
   главного экрана — предложенная дата 16.09, следующая 30.09.
5. **Дедлайн от открытого дня.** Открыть 08.09, нажать «+» на паре «Инновации» — выбора
   предмета нет, дата по умолчанию 08.09, второй пресет 15.09.
6. **Ручная дата.** Изменить дату полем ввода — автоподстановка больше не перебивает выбор.
7. **Группировка и сортировка.** Задания на вчера, на эту неделю, на следующую и через месяц
   попадают в четыре разных блока; внутри блока дни идут по возрастанию.
8. **Просрочка.** Задание с прошедшей датой в блоке «Просрочено» с подписью вида «2 дня назад».
9. **Выполнение.** Отметить задание — исчезает из блоков, появляется в свёрнутом списке
   «Выполненные»; повторный тап возвращает.
10. **Сохранение.** Перезагрузить страницу — задания на месте. Экспортировать, очистить,
    импортировать — данные восстановились.
11. **Изменение расписания.** Добавить пару, создать предмет прямо из формы пары, удалить
    пару — экран дня отражает изменения; существующие задания не пропали.
12. **Темы.** Тумблеры «Ночная тема» и «Режим сдвгшника» переключают оформление целиком,
    взаимоисключают друг друга, выбор переживает перезагрузку.
13. **iPhone.** Ссылка открывается в Safari, ставится на домашний экран, запускается без
    адресной строки, под нижней навигацией нет лишней пустоты.
