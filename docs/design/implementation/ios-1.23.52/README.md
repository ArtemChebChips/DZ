# Проверка iOS — 1.23.52

27.09.2026. Проверка через Computer Use в Device Hub на **iPhone 17, iOS 27.0 Simulator**. Это настоящая среда iOS в симуляторе, не физический телефон. Проверялась локальная копия приложения; Safari — деморежим, установленный ярлык — отдельное хранилище localhost:4186. Рабочее хранилище владельца и старые ярлыки не очищались.

## Календарь: воспроизведено и исправлено

В Safari нажата кнопка календаря: открылась только шапка, сетка отсутствовала. После стрелки месяца сетка появилась. Таким образом, жалоба владельца воспроизведена на iOS, прежних проверок наличия DOM оказалось недостаточно.

Причина в раскладке: все страницы были absolute, высоту контейнера задавал Calendar в layout effect. В момент первого измерения родительский dialog ещё закрыт, высота сетки нулевая. Следующий месяц измерялся уже после открытия окна.

Текущая страница теперь находится в нормальном потоке и сама задаёт высоту. Только уходящая страница позиционируется абсолютно. Размеры измеряются лишь для перехода между уже видимыми месяцами; при разном числе строк высота анимируется временно, затем снова естественная. Постоянного inline height нет.

## Нажатия: исправлено

Ранее `box-shadow` включался резко на всей кнопке, включая прямоугольную область даты. Теперь затемнение плавно входит и выходит (90/140/242 мс по скорости), у даты рисуется на круглом `::before`; площадь касания не уменьшена. Reduced motion убирает переход. Нет новой обводки, масштабирования или изменения размеров.

В iOS нажаты «Задание», выбор предмета, дата и крестик; сняты последовательные кадры открытия и [круглой даты](date-circle.png). Принятая анимация окна не менялась. Серое свечение указателя на снимках рисует инструмент управления, оно не является частью интерфейса приложения.

## Верхняя полоса: НЕ исправлена

Обычный Safari iOS: светлая → тёмная → светлая меняет верхнюю область корректно. Установленная копия: после запуска на светлом фоне и перехода в чёрную тему [системная область остаётся белой](standalone-bar.png). После перезагрузки на чёрном фоне и выбора светлого — остаётся чёрной.

[Временное измерение viewport](viewport.png): `screen.height=874`, `innerHeight=812`, `documentElement.clientHeight=812`, `visualViewport.height=812`. Верхний padding шапки 16 px — базовый padding без safe area, то есть safe-area-inset-top=0. Разница 62 px находится над web viewport. Поэтому перекрашивание DOM-элемента `#system-top` само по себе эту область не обновляет.

Проверка `black-translucent` в документе с повторной загрузкой существующей тестовой установки не решила проблему: полоса по-прежнему сохраняла цвет запуска. Изменение откачено. Динамический выбор black/default начат как локальная диагностика, но не подтверждён после сбоев запуска; также откачен. В выпуске нет новых метатегов, reload-обходов или диагностической панели. Не выдавать эти эксперименты за исправление и не советовать переустановку.

Наблюдение соответствует [WebKit 301994](https://bugs.webkit.org/show_bug.cgi?id=301994), где описана отдельная область вне viewport и подтверждено воспроизведение iOS 27. Это основание оставить проблему открытой, а не доказательство отсутствия любого возможного обхода. Нужна проверка последующих исправлений iOS/WebKit или отдельно проверенное решение без перезагрузки и потери черновика.

## Управление Device Hub и границы проверки

В этот раз удалось выполнить касания и открыть Safari/установленный ярлык. Надёжный ввод адреса: `setValue` адресного поля, затем экранная кнопка «Перейти». `pressKey` и обычный ввод добавляли посторонние символы; вставка вернула timeout. Нативные AX-нажатия иногда не срабатывали, координатные нажатия по свежему снимку работали.

Попытка запустить установленный iPhone 13/iOS 27 привела к тайм-аутам и `noWindowsAvailable`; устройство не проверено. Штатное завершение Device Hub и повторное открытие восстановили окно, iPhone 17 удалось запустить снова. Локальный ярлык некоторое время показывал белый экран при работе с dev-сервером. После перехода на готовую production-сборку приложение загрузилось; проверены первое открытие сетки и сценарий 28 сентября → октябрь → «Текущий месяц» с сохранением выбранного 28-го и открытого окна. Нестабильную горячую перезагрузку не считать проверкой холодного запуска опубликованного PWA. Ни устройства, ни данные не стирались. Жесты drag/scroll через инструмент не дали надёжного результата; проверка нативных свайпов в этом выпуске остаётся открытой.
