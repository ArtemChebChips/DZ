# Проверки актуальной версии «ДЗ»

Основа: текущая `design/`-реализация от `c218703`; итоговая проверяемая сборка 1.23.58. Проверки прежнего приложения из ветки `codex/audit-legacy` сюда не переносятся как результаты текущего приложения.

## Автоматические проверки логики

Команда: `node --experimental-strip-types --test tests/*.test.mjs` (или `npm run test:next`).

Исходные 45 проверок прошли. Добавлено 11 проверок в `tests/calendar-regression.test.mjs`; итог **56/56 прошли**:

- Локальные даты, отрицательный часовой пояс, начало/конец DST, високосный февраль и Новый год.
- Годы 0000–0100 одинаково понимаются валидатором хранения и календарными функциями.
- Чётность до якоря и после него, непрерывные номера учебных недель.
- Целостность настоящего расписания: 11 предметов, 28 правил, уникальные идентификаторы, корректное время и ссылки.
- Ближайшие даты семинаров/лаб, включение сегодняшнего дня, две лабы в один день, отсутствие дубликатов; найденная дата действительно содержит нужную пару.
- Группировка без потери и дублирования заданий на границах года/месяца; соответствие существующему правилу «сегодня — просрочено».
- Связь со второй лабораторной и отсутствие ложного перерыва в ВУЦ.
- Короткий/пустой набор примеров и сохранение личных записей при удалении тестовых.
- Пустой существующий ключ не считается первым запуском и не заменяется умолчаниями.
- Единый порог и выбор оси для свайпа/прокрутки.

Полностью прочитаны: `design/academic-week.ts`, `breaks.ts`, `current-interval.ts`, `history.ts`, `homework.ts`, `task-groups.ts`, `task-summary.ts`, `test-tasks.ts`, `data.ts`, `use-today.ts`, `src/lib/dates.ts`, `week.ts`, `src/data/schedule.ts`, `src/types.ts`. Проверки агента в `tests/smart-input.test.mjs` прошли как часть существующего набора. Дополнительно проверена только интеграция сохранения предложений агента с полностью замоканным HTTP-ответом; распознавание и поведение живой модели не оценивались.

## Браузерные проверки

`tests/browser/audit.mjs` использует встроенный `node:test` и доступный Playwright. Зависимости приложения не меняются. Пример запуска с библиотекой из desktop runtime:

```sh
DZ_PLAYWRIGHT_PATH=/путь/к/dependencies/node/node_modules/playwright \
DZ_CHROME_PATH='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' \
DZ_BASE_URL=http://127.0.0.1:43187/ \
DZ_DEV_BASE_URL=http://127.0.0.1:43189/ \
node --test tests/browser/audit.mjs
```

`DZ_PLAYWRIGHT_PATH` можно опустить при обычной установке `playwright`; `DZ_CHROME_PATH` — при установленном Chromium Playwright. `DZ_DEV_BASE_URL` нужен только для одного теста DEV-пилота агента; без него этот тест явно пропускается. Остальные сценарии тестируют production-сборку `npm run build:design`, отданную локальным preview. Все профили и записи синтетические, рабочие данные владельца не читаются.

Проверяются: три вкладки; создание/правка/удаление и отмена; выполнение/история/возврат; текущий и выбранный день; точная пара физики и следующая дата; явный выбор второй лабораторной; заметка с лекции; темы/скорость/сворачивание/экспорт; замена и очистка примеров; повреждённая база и точная выгрузка исходных байтов; ошибка записи и резервная копия данных из памяти; изоляция демо; короткая высота редактора и клавиатурный фокус; полночь; перезагрузка и новое окно офлайн; два окна одного origin; конфликт внешней записи с несохранённой локальной; отмена отложенного тапа при прокрутке; динамический reduced-motion; единая ось диагонального жеста; черновик при перетаскивании из поля на подложку.

Две ошибки подтверждены до исправлений браузером:

1. Два окна: после записи A в первом и B во втором в хранилище оставалась только B. Регрессия требует сохранения обеих записей и обновления интерфейса обоих окон.
2. Диагональ: при движении `(0,-7)`, затем `(-220,-20)` одновременно менялись `scrollTop` на 20 px и горизонтальный offset на −220 px. Регрессия проверяет единую ось при обоих вариантах первого движения.

Дополнительная проверка настоящих одновременных сохранений обнаружила потерю данных после первого исправления хранения: две заполненные формы сохранялись через `Promise.all(click A, click B)`, уже в раунде 0 вместо двух записей сохранилась одна. После исправления с Web Locks все **40 записей в 20 раундах** сохранены. Тест не подменяет storage и не внедряет mock в приложение. Он проверяет конкурентные операции текущей реализации; это не доказательство атомарности произвольного прямого доступа к localStorage сторонним кодом.

Дополнительные регрессии проверяют отсутствие Web Locks и отказ блокировки без перезаписи исходного сохранения; ожидающие блокировку сохранение и удаление с повторной отправкой; сохранность нового черновика после Escape и позднего завершения старой операции; прерывание доведения дня новым касанием; правильный месяц для года 0001. Два теста с подменённым `navigator.standalone` проверяют решение о перезагрузке после смены темы: обычное изменение вызывает предусмотренный reload, а отложенное изменение после открытия нового черновика его сохраняет. DEV-тест отказа и повтора сохранения предложений агента выполняет один mocked-разбор и создаёт ровно одну запись.

Итог окончательного прогона на замороженных исходниках 1.23.58: **28/28 браузерных сценариев прошли, 0 пропущено** — 27 production и 1 DEV с замоканным `/agent/parse`, 19.7 s. Повторный окончательный запуск логики: **56/56 прошли**. Метаданные результата: `audit/browser-results.json`.

Нагрузка: 1000 синтетических заданий на 28 дней, Chromium 390×844; измеряются время переключения на задачи, количество записей и DOM. Это ориентир локальной машины, без нестабильного порога «обязательно быстрее N ms».

Последний замер 1.23.58: запуск 100 ms, переход к задачам до двух следующих кадров 83 ms, 1000 строк задач, 9408 DOM-элементов, все 1000 записей сохранены. Все восемь снимков обновлены после окончательного source freeze для 1.23.58.

## Ограничения

Chromium с мобильным viewport, искусственными часами и синтетическими touch events не заменяет реальный iPhone. WebKit Playwright не установлен (`webkit-2336/pw_run.sh` отсутствует), поэтому WebKit smoke не выполнен; браузер не скачивался. Не проверены физические клавиатура, микрофон, VoiceOver, настоящий Safari/standalone, сохранность после выгрузки PWA самим iOS и реальная частота экрана. Mock standalone проверяет только frontend-решение о reload. Офлайн «новое окно» использует существующий browser context и установленный service worker; это не перезапуск операционной системы. Импорта JSON в текущем интерфейсе нет, поэтому его отсутствие не записывается как баг. Живые запросы к Claude, распознавание аудио и сервер не запускались.
