# ДЗ · версия Codex

Мобильная PWA: домашние задания по срокам, календарь и настоящее двухнедельное расписание.

- Прежняя версия: https://artemchebchips.github.io/DZ/
- Новая версия: https://artemchebchips.github.io/DZ/codex/
- Разработка новой версии: `codex/redesign`.
- Исходная версия Claude: `archive/claude-mvp-2d75887`, commit `2d7588703b042ac6dcb6ef622bf2f2a2365a2442`.

## Возможности

Главный экран группирует задания по неделям и дням, крупно показывает срок сдачи. Календарь учитывает числитель и знаменатель от понедельника 31.08.2026. Добавление с пары сохраняет выбранные предмет и день; при добавлении с главного экрана предлагается ближайшая следующая пара. Есть выполненные задания, редакторы расписания и предметов, три темы, экспорт и импорт резервной копии.

Данные версий разделены: новая использует `dz:codex:data`, `dz:codex:theme`, `dz:codex:device`. Старые ключи не читаются и не изменяются. Для переноса нужно выгрузить резервную копию в старой версии и загрузить в новой через настройки. Импорт принимает формат версии 2, проверяет данные и полностью заменяет содержимое новой версии после подтверждения. Синхронизации между устройствами нет.

## Разработка

Node.js 24, npm. Зависимости и исходное расписание сохранены из прежнего проекта.

```sh
npm ci
npm run dev
npm test
npm run build
```

Для сборки нового публичного адреса нужно окружение `BASE_PATH=/DZ/codex/`.

## Совместная публикация

Workflow `.github/workflows/deploy.yml` берёт старое приложение из `main`, новое из `codex/redesign`. Он отдельно собирает обе PWA и размещает их в одном артефакте Pages. В `main` меняется только workflow, функциональный код старого приложения сохраняется.

`prepare-legacy.mjs` правит только временную сборочную копию старой PWA: исключает `/DZ/codex/` из navigation fallback, отключает очистку чужих кешей и добавляет переходный обработчик для старого service worker. Сам архивный commit не изменяется. Скрипт останавливает публикацию, если прежняя конфигурация существенно изменилась, чтобы не сломать одну из версий.

Push в `main` публикует обе версии. Push в `codex/redesign` проверяет обе сборки; для публикации после этого запусти `Publish both app versions` в GitHub Actions с веткой `main`. Так сохраняется существующее ограничение среды GitHub Pages на публикации из main. Не заменяй этот workflow обычной публикацией одного `dist`, иначе вторая ссылка исчезнет.

## Проверки

`npm test` проверяет границы дат, чётность до и после якоря, реальные пары, двухнедельные дедлайны, воскресную группировку, сортировку, импорт, сохранение и разделение данных. Совместная сборка дополнительно проверяет manifests, области PWA и разделение файлов кеширования.

На реальном iPhone отдельно нужно проверить установку, авиарежим и экранную клавиатуру. При первом переходе со старой установленной PWA может понадобиться дать ей обновиться онлайн. В новой версии обновление предлагается кнопкой, чтобы не перезагрузить открытый редактор без предупреждения.
